# SIMD

This proposes to provide access to SIMD instructions to OCaml programmers. This
RFC describes (a subset of) the design currently implemented in Jane Street’s
OxCaml.

The API would make use of the following 128 and 256-bit vector types:

```
int8x16         int8x32
int16x8         int16x16
int32x4         int32x8
int64x2         int64x4
float32x4       float32x8
float64x2       float64x4
```

Within a function, all SIMD vectors live in floating-point registers or 16-byte
aligned stack slots.

Since mainline OCaml does not have unboxed types, SIMD vectors are boxed. When
passed to a non-inlined function, they will be copied to a heap-allocated
(abstract) block. Boxed vectors are not necessarily aligned, so will generate
unaligned load/store instructions.

## Intrinsics

The compiler will translate certain “builtin” externals directly to SIMD
instructions. These intrinsics should be exposed via an API like Jane Street’s
[ocaml_simd_avx](https://github.com/janestreet/ocaml_simd/tree/with-extensions/avx)
or
[ocaml_simd_sse](https://github.com/janestreet/ocaml_simd/tree/with-extensions/sse).
For instance:

```ocaml
module Float32x4 = Ocaml_simd_sse.Float32x4

let v = Float32x4.set 1.0 2.0 3.0 4.0
let v = Float32x4.sqrt v
let x, y, z, w = Float32x4.splat v
```

SIMD vectors may be loaded from / stored to strings, bytes, and bigstrings.

```ocaml
module Int8x16 = Ocaml_simd_sse.Int8x16

let text = "abcdefghijklmnopqrstuvwxyz"
let floats = [| 1.0; 2.0 |]

let _ = Int8x16.String.get text ~byte:0
let _ = Float64x2.Float_array.get floats ~idx:0 (* Float array optimization required *)
```

Some operations require the user to choose a specific behavior at compile time.
To do so, one must provide a compile time constant. For easier use, such a
constant can be generated by a PPX such as [`ppx_simd`](https://github.com/janestreet/ocaml_simd/tree/with-extensions/ppx).

```ocaml
module Int32x4 = Ocaml_simd_sse.Int32x4

let x = Int32x4.set 0 2 4 6
let y = Int32x4.set 1 3 5 7
let z = Int32x4.blend [%blend 0, 1, 0, 1] x y
```

## C ABI

Like floats, SIMD vectors may be passed to C stubs. The OCaml runtime will
provide several helper functions for working with SIMD vectors.

```ocaml
external vec128_stub : (int8x16[@unboxed]) -> (int8x16[@unboxed]) =
  "boxed_vec128_stub" "unboxed_vec128_stub"

external vec256_stub : (int8x32[@unboxed]) -> (int8x32[@unboxed]) =
  "boxed_vec256_stub" "unboxed_vec256_stub"
```

```c
#include <caml/simd.h>

__m128i unboxed_vec128_stub(__m128i v) {
  return v;
}
__m256i unboxed_vec256_stub(__m256i v) {
  return v;
}

value boxed_vec128_stub(value v) {
  return caml_copy_vec128i(unboxed_vec128_stub(Vec128_vali(v)));
}
value boxed_vec256_stub(value v) {
  return caml_copy_vec256i(unboxed_vec256_stub(Vec256_vali(v)));
}
```

## Implementation

Currently, only support for amd64 SIMD instructions has been implemented in
OxCaml, up to and including AVX2. Support for NEON and AVX512 is in progress.

128-bit and 256-ibt SIMD vector types are added as new builtin types. In the
native backend, inside functions, they are stored in floating-point register or
16-byte aligned stack slots. Between functions and in bytecode, they are boxed
and allocated as abstract blocks.

The new builtins for SIMD operations on vectors are compiled to the
corresponding assembly instructions.
